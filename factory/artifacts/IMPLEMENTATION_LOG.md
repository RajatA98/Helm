## Entry 3 — 2026-09-12

- **Phase:** Phase 1. Slice 3 of 6: the scene as a pure view.
- **Goal:** Turn the approved prototype into a scene the app can drive: no HTML UI of its own, one `setState` call in, tap events out, offline.
- **Tests / Validation Targets:** 16 node tests in `SceneTests/scene-logic.test.js` (all passing with `npm test`): contract version, condition boundaries, state normalizing (JSON or object, version mismatch throws, condition derived from leaks, defaults filled, time clamped), override hours, condition-to-visual parameters, heading lookup, sun elevation and azimuth, event building (version stamped, `islandTapped` needs an id), hex color parsing, deterministic mock state. Browser validation with Playwright: loads with no script errors; `setState` with 4 leaks at 7 pm shows four puddles and a listing ship at sunset; 5 leaks at 2 am heading to "hired" shows a lowered, listing ship at night turned toward the other island; a wrong version is rejected and reported as `sceneError`; pause and resume work.
- **Files Changed:** `Scene/index.html`, `Scene/scene.js`, `Scene/scene-logic.js`, `Scene/vendor/three.min.js` (three.js r149, bundled, no CDN), `SceneTests/scene-logic.test.js`, `package.json`.
- **Implementation Summary:** All pure logic lives in `scene-logic.js` and runs under Node for tests; `scene.js` only draws. The scene exposes `window.helmScene.setState / playEvent / pause / resume` and posts `sceneReady`, `sceneStats` (fps, load time, every 2 s), and tap events through the `helm` message handler. In a plain browser (no WKWebView) it logs messages instead and turns the ship itself when the wheel is tapped, so design work still works standalone. Islands are built from the state's island list (deterministic per id), the cove lighthouse is a fixed landmark, puddles and listing come from the ship condition, avatar and ship colors are applied to materials (the hull texture is regenerated for a new hull color; the sail color goes on a jib), and time of day comes from the state, with an optional override.
- **Known Issues:** The ocean is still the prototype's semi-realistic look; the stylized toon ocean from the plan is a follow-up. `playEvent` accepts moments but plays no animation yet (later phases). The scene has no `sceneError` type in the Swift contract; the app treats it as an unknown event and logs it (added to the contract doc as a follow-up).

## Entry 4 — 2026-09-12

- **Phase:** Phase 1. Slice 4 of 6: the scene inside the app.
- **Goal:** Run the bundled scene in a WKWebView behind SwiftUI, with a tested bridge object carrying state out and events in, a load timeout with a calm fallback, and a message log for the debug screen.
- **Tests / Validation Targets:** 10 new tests in `HelmTests/SceneBridgeTests` (all passing on the iPhone 16 Pro simulator): the `setState` call wraps the JSON as a JavaScript string literal (quotes and newlines escaped), sending is logged as outbound, `sceneReady` marks the scene ready, stats update the latest reading, tap events are forwarded, an unknown type is logged and forwarded as `.unknown`, an incompatible version is logged and not forwarded, a malformed body is logged and never fatal, a load failure is recorded and a late `sceneReady` recovers it, the log keeps only the last 50 entries. Validation: the app installed and launched in the simulator shows the ship scene full screen from the bundled files.
- **Files Changed:** `Helm/Scene/SceneBridge.swift` (new), `Helm/Scene/SceneView.swift` (new, includes `SceneFallbackView`), `project.yml` (the `Scene/` folder is bundled as a folder reference), `HelmTests/SceneBridgeTests.swift` (new), `docs/run-on-device.md` (new).
- **Implementation Summary:** `SceneBridge` is the native end of the contract and knows nothing about WKWebView: it builds the JavaScript for `setState`, parses incoming messages into `SceneEvent`s, tracks load state (loading, ready, failed), keeps the latest fps and load-time reading, and logs every message in a 50-entry ring buffer. `SceneView` wraps a WKWebView that loads `Scene/index.html` from the app bundle (no network), registers the `helm` message handler, forwards navigation failures and web-process termination to the bridge, and starts a 4-second load timeout; if the scene never reports ready the app shows a calm "Becalmed" fallback instead. Swift 6 strict concurrency stayed on; the bridge and coordinator are main-actor isolated.
- **Known Issues:** The scene's `sceneError` message isn't a named event in the Swift contract yet; it arrives as `.unknown(type: "sceneError")` and is logged, which is enough for Phase 1.
