## Entry 2 — 2026-09-12

- **Phase:** Phase 1. Slice 2 of 6: the scene contract in HelmCore.
- **Goal:** Pin down, in tested Swift types, exactly what the app sends the 3D scene and what the scene sends back, so both sides can be built against the same shape.
- **Tests / Validation Targets:** 11 new tests in `SceneContractTests` (all passing with `swift test`): ship condition boundaries (0, 1, 2, 3, 4, 5, 9, negative), condition re-derives when leaks change, state round-trips through JSON, state carries the contract version, JSON keys are stable and sorted, `timeOverride` is omitted when unset, every known event decodes, an unknown event type decodes to `.unknown` instead of throwing, a version mismatch is detectable, missing `version`/`type` throws, `islandTapped` without an id throws.
- **Files Changed:** `HelmCore/Sources/HelmCore/SceneContract.swift` (new), `HelmCore/Tests/HelmCoreTests/SceneContractTests.swift` (new), `docs/scene-contract.md` (new, the human-readable contract).
- **Implementation Summary:** `SceneState` is the whole picture the app sends: open leaks, the ship condition derived from them, the heading, time of day (plus an optional override), the islands, the crewmate and their line, avatar options and ship design. It encodes with sorted keys so identical state always produces identical JSON. `SceneEventEnvelope` decodes messages from the scene into a `SceneEvent`; unknown types are tolerated and version mismatches are flagged rather than fatal.
- **Known Issues:** None.
